# clock v0.2.8

`iclock.html` は、ブラウザでローカル実行できるデジタル時計・タイマー・予定時刻表示です。HTML、CSS、JavaScriptを1ファイルに含めており、サーバー、npm、ビルド、CDN、外部API、外部フォント、外部ライブラリは不要です。外部通信は行わず、個人情報や利用情報を外部送信しません。

## 起動方法

1. リポジトリ直下の `iclock.html` をChromium系ブラウザで直接開きます。
2. 音声読み上げを使う場合は、画面右上の「音声を有効化」を一度クリックします。ブラウザの自動再生制限により、初回はユーザー操作が必要です。

画面上部のタブで「時計」「タイマー」「予定時刻」を切り替えます。「設定」ボタンでは、そのとき表示しているモードの設定を編集し、「設定を保存」で確定します。

## 時計モード

`HH:MM` を等幅数字で大きく表示し、秒を右下、日付を下部に小さく表示します。

## タイマーモード

* 設定パネルで「残り時間（分）」（1〜1440分）と「開始時刻」を設定します。
* 開始、一時停止、再開、リセットを操作できます。残り時間は `MM:SS`、1時間以上では `HH:MM:SS` で表示します。
* 開始時刻を設定すると、その時刻を通過したときにタイマーを自動開始します。自動開始は途中経過を引き継がず、常に設定した残り時間から数え直します。
* 設定を保存しても、計測中のタイマーはそのまま継続します。「残り時間（分）」を変更したときだけ、新しい残り時間で最初から数え直します。
* Spaceで開始／一時停止／再開、Rでリセットします。入力欄の編集中、設定パネル表示中、CtrlやCommandなどの修飾キー併用時は反応しません。Escapeはどのモードからでも設定パネルを閉じます。
* 残り時間は画面更新回数ではなく経過時刻から計算するため、描画遅延や非アクティブタブからの復帰でも累積ずれが起きません。

## 予定時刻モード

会議や研修などの進行確認向けに、登録した予定のうち現在時刻に対して次に来る予定と残り時間を大きく表示します。

* 予定は最大10件まで登録できます。設定パネルで各予定の有効／無効、時、分、名称、読み上げ有効／無効、読み上げ文章を編集し、「予定を追加」「上へ」「下へ」「削除」で登録順を調整します。初期状態では予定が空なので、設定から追加してください。
* 有効な予定だけを時刻順に判定します。同じ時刻の予定が複数ある場合は登録順を維持します。
* 次の予定までを「あと `MM:SS`」、1時間以上では「あと `HH:MM:SS`」と表示します。
* 当日の次の予定がない場合だけ、最後の予定から「超過表示時間」（初期値10分）の間を「超過中」と表示します。色だけに依存せず、文字と枠でも区別します。
* 超過表示時間も過ぎると「本日の予定は終了しました」と表示します。
* 予定ごとの読み上げは、同じ日の同じ予定につきページ再読込後も1回だけ発火します。日付が変わると読み上げ済み状態をリセットします。

## 読み上げ設定

ブラウザ標準の Speech Synthesis API を使用します。音声の種類、再生可否、発音品質はブラウザとOSの実装に依存します。

* 時計読み上げは最大5件です。有効、時、分、秒、文章を設定できます。同じ日の同じ条件は1回だけ発火し、「時計読み上げ状態をリセット」で再判定できます。
* タイマー読み上げは最大5件です。有効、残り分数、文章を設定できます。同じタイマー実行中は1回だけ発火します。設定したタイマー時間と同じ残り分数は開始直後に読み上げ、一時停止からの再開では読み上げ直しません。
* 読み上げ速度は0.5〜1.5倍で設定でき、「読み上げテスト」で確認できます。
* 読み上げは最大5件のキューで順番に処理します。リセットや設定変更など、古い発話が不要になる操作ではキューと現在の発話を取り消します。タイマーの計測は読み上げの完了を待たずに進みます。

## テーマと設定の保存

テーマの初期状態はOS設定に追従し、OS側の切替にもその場で追従します。「テーマ切替」でライト／ダーク固定に変更できます。

設定はこのブラウザの `localStorage` に保存されます。保存対象は、最後のモード、テーマ、時計読み上げ、タイマー読み上げ、タイマー残り時間、開始時刻、予定一覧、予定超過表示時間、予定読み上げ、読み上げ済み日付状態、音声速度です。保存値の一部が壊れていても、範囲内へ丸めたうえで他の設定は保持します。「設定を初期化」で保存内容と表示を初期状態へ戻します。

## GitHub Pages

公開先URLは `https://yantkys.github.io/clock/` です。`main` ブランチの `iclock.html` からGitHub Actionsで `_site/index.html` を生成して公開します。アプリ本体の正本はリポジトリ直下の `iclock.html` のみで、`index.html` はリポジトリでは管理せず、公開用成果物としてのみ生成します。

初回は、GitHubの `Settings` → `Pages` → `Build and deployment` → `Source` を `GitHub Actions` に設定してください。設定を自動化する場合は、Pagesの書き込み権限を持つPersonal Access TokenをリポジトリSecret `PAGES_TOKEN` に登録すると、workflow内の `actions/configure-pages` がPages有効化を試行します。どちらも未設定の場合は、デプロイ時にPages未有効化エラーになります。

## 動作確認環境

Chromium系ブラウザを主対象に実装しています。表示の切替、タイマーの計測と終了、予定の残り時間・超過・終了表示、ショートカット、設定の保存と初期化は、Chromiumを自動操作して仮想時刻を進める方法で確認しています。主表示が画面幅に収まることは、16:9、4:3、5:4の横長・縦長で `MM:SS` と `HH:MM:SS` の両方について確認しています。

## 既知の制限

* 実行中のタイマー状態は保存されません。計測中にページを再読込すると、停止状態から始まります。
